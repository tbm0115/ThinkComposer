# Modeling gaps and second pass backlog

The Domain mechanism is useful for prototype vocabulary, structured model data and a limited textual export. It does not supply SysML's semantic services or specialized diagram editors. The next pass should first make data and export failures visible, then expand validated semantics. Replacing a generic Concept Definition name with a language metatype name does not implement that metatype.

Specification references use named sections to avoid mixing clause numbering across editions: [SysML 1.6](https://www.omg.org/spec/SysML/1.6), [UML 2.5.1](https://www.omg.org/spec/UML/2.5.1), [SysML 2.0](https://www.omg.org/spec/SysML/2.0), [KerML 1.0](https://www.omg.org/spec/KerML/1.0). Exact version assumptions are recorded in `sources/validation-tools.json`.

## Priority order

1. Establish trustworthy export failure reporting, parser/profile validation and library/reference checks (G01, G02, G07, G08, G20). This is necessary before these files can support published standards definitions.
2. Resolve full-model performance and document loss checks (G05, G21). Reuse the supplied source as a regression fixture without modifying it.
3. Improve Domain defaults, namespace-aware references, MT metadata and requirement/behavior/constraint mappings (G09–G18). Prefer Domain or external tooling improvements where they suffice.
4. Implement specialized diagram editing and broaden compatibility only after the semantic subset is validated (G06, G19).

The distinction between prototype and conforming tool is semantic validation, interoperable interchange and correct notation, not simply a larger palette of named shapes. This pass makes those boundaries inspectable without changing application source.
