# AI-Readable Container Snapshots

ThinkComposer `.tcom` and `.tdom` files are package containers. Modern saves use root JSON persistence parts as the native source of truth:

- `/Composition.json` for compositions.
- `/Domain.json` for domains and embedded composition domains.
- `/TemplateComposition.json` for optional domain template compositions.

Legacy binary-only and transitional packages may also contain `/Composition.bin` or `/Domain.bin`. Those parts are fallback/recovery payloads only. Current saves do not write them.

Current builds also write non-authoritative sidecar parts so tools and AI assistants can inspect saved files without first running a separate JSON export.

## Package Parts

Composition saves write:

- `/manifest.json`
- `/Composition.json`
- `/Domain.json`
- `/Interchange/manifest.json`
- `/Interchange/Composition.json`
- `/Interchange/Domain.json`
- `/Previews/views/*.png`

Domain saves write:

- `/manifest.json`
- `/Domain.json`
- `/Interchange/manifest.json`
- `/Interchange/Domain.json`

When a `.tdom` save includes a template composition, it can also write:

- `/TemplateComposition.json`
- `/Interchange/TemplateComposition.json`
- `/Previews/views/*.png`

The root manifest uses `format: "ThinkComposer.Package"` and `formatVersion: 1`; its schema is maintained at `docs/thinkcomposer-package-manifest.schema.json`. Current saves emit `legacyBinaryFallback: { "present": false }` without a binary URI or hash. The manifest may also contain optional `gitSync` metadata with `version: 1`, a generic Git remote URL, branch, and repo-relative baseline package paths. Composition packages may additionally contain optional `embeddedDomainGitSync` metadata for the embedded Domain's source `.tdom` link. The sidecar manifest uses `format: "ThinkComposer.ContainerSnapshot"` and `formatVersion: 2`; its schema is maintained at `docs/thinkcomposer-container-manifest.schema.json`.

## Behavior

The root JSON payload is generated by the same Composition JSON and Domain JSON exporters used by the manual export commands, then loaded through a persistence rehydration path instead of a merge/import dialog. Opening a modern native file reads root JSON first. Opening a legacy binary-only file still reads the exact matching `/Composition.bin` or `/Domain.bin`; saving it migrates the package to JSON-only persistence. If authoritative JSON is present but corrupt, fallback occurs only when that matching legacy part physically exists. A package with neither authoritative JSON nor its matching binary part fails explicitly.

Preview images remain 1600x1200 PNGs and are capped at 20 views. Sidecar manifest v2 associates each preview with stable `viewId`, a deterministic `inputSha256`, and a `renderProfile`. `disposition` reports `rendered`, `reused`, or `empty`; `sha256` continues to hash the actual PNG bytes. On a later save, ThinkComposer verifies the prior manifest entry and PNG byte count/hash before copying an unchanged preview into the new package. Changed views are rerendered, while Domain/style or renderer-profile changes conservatively invalidate affected previews. Missing, v1, mismatched, oversized, or corrupt caches are ignored and regenerated. Save As reuses only the open document's source package, never an unrelated destination file.

Authoritative root JSON and `/manifest.json` are required writes; failure aborts the save and preserves the original package. `/Interchange/*` and preview generation are optional. A sidecar failure records a warning but does not invalidate an otherwise successful native save. Sidecar `nativePartUri` and `nativePartSha256` identify the authoritative root `/Composition.json` or `/Domain.json`, not a legacy binary part.

Git synchronization is metadata-driven and optional. `gitSync` and `embeddedDomainGitSync` do not make Git or `/Interchange/*` authoritative; normal Open/Save still reads root `/Composition.json`, `/Domain.json`, and `/TemplateComposition.json`. Commit hashes and package hashes are stored in machine-local ThinkComposer Git sync state so the package does not try to embed the commit that contains itself.

## AI Workflow

An AI tool can inspect a saved package by opening it as a zip/OPC package and reading:

1. `/manifest.json`
2. root `/Composition.json`, `/Domain.json`, or `/TemplateComposition.json`
3. `/Interchange/manifest.json`
4. the listed sidecar JSON parts
5. the listed preview PNGs

If embedded sidecars are missing or stale, inspect and patch the authoritative root JSON first. For explicit compatibility exports or visual verification, use:

- `thinkcomposer composition export-json --input <file.tcom> --output <file.json>`
- `thinkcomposer domain export-json --input <file.tdom> --output <file.json>`
- `thinkcomposer git status --input <file.tcom|file.tdom>`
- `Export Image`

## Migration Notes

Legacy binary-only and transitional `.tcom` and `.tdom` files remain readable. Newly saved files are JSON-authoritative and binary-free; resaving a legacy/transitional file is the migration step.

Root JSON currently covers the documented Composition JSON and Domain JSON fields. Metadata-only warnings in the root JSON or package manifest identify native data that is intentionally not reconstructed from JSON, such as binary attachment payloads or custom binary image resources.
