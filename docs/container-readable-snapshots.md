# AI-Readable Container Snapshots

ThinkComposer `.tcom` and `.tdom` files are package containers. The native binary parts remain authoritative:

- `/Composition.bin` for compositions.
- `/Domain.bin` for domains.

Current builds also write non-authoritative sidecar parts so tools and AI assistants can inspect saved files without first running a separate JSON export.

## Package Parts

Composition saves write:

- `/Interchange/manifest.json`
- `/Interchange/Composition.json`
- `/Interchange/Domain.json`
- `/Previews/views/*.png`

Domain saves write:

- `/Interchange/manifest.json`
- `/Interchange/Domain.json`

When a `.tdom` save includes a template composition, it can also write:

- `/Interchange/TemplateComposition.json`
- `/Previews/views/*.png`

The manifest uses `format: "ThinkComposer.ContainerSnapshot"` and `formatVersion: 1`. Its schema is maintained at `docs/thinkcomposer-container-manifest.schema.json`.

## Behavior

The embedded JSON is generated by the same Composition JSON and Domain JSON exporters used by the manual export commands. Opening a native file still reads the binary part; the embedded JSON is a synchronized snapshot for inspection, review, GPT context, and future recovery work.

Preview images are PNG v1. They are capped to keep saves safe and predictable. If a view has no renderable content, or a preview cannot be generated, the save still succeeds and the manifest/log records a warning.

Sidecar generation is non-blocking. A failure to write JSON or previews should not prevent a normal `.tcom` or `.tdom` save.

## AI Workflow

An AI tool can inspect a saved package by opening it as a zip/OPC package and reading:

1. `/Interchange/manifest.json`
2. the listed JSON parts
3. the listed preview PNGs

If embedded sidecars are missing or stale, use the normal manual commands:

- `Composition > File > Export JSON...`
- `Domain > Export Domain JSON...`
- `Export Image`

## Parity Roadmap

The binary parts are not replaced in this version. JSON may become authoritative only after the interchange reaches full parity for native persistence, including model identity, visuals, details, attachments, rich content, styles, complements, shortcuts, relationship links, undo-safe load repair, and save/reopen compatibility.

Until that milestone, native `.tcom` and `.tdom` files remain the source of truth.
