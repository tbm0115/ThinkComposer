# Updating a Composition's Embedded Domain

ThinkComposer compositions (`.tcom`) embed a snapshot of the domain that was used when the composition was created or last updated. They do not maintain a live link to a `.tdom` file.

The command `Composition > Domain > Update Embedded Domain...` explicitly merges a newer domain source into the active composition's embedded domain snapshot.

## Supported Sources

The update command accepts:

- Native ThinkComposer domain files: `*.tdom`
- Domain JSON Interchange files: `*.tdom.json` or `*.json` with `format: "ThinkComposer.DomainJsonInterchange"`

Native `.tdom` files are loaded with the existing ThinkComposer domain loader. Domain JSON files are parsed as interchange documents and merged through the same safe Domain JSON planner/applier used by domain import.

## Safe Merge Behavior

The embedded-domain update is previewed before it is applied. Matching uses id/GlobalId first, then `techName`, then owner plus `techName` for child entities.

The merge can:

- Add missing concept definitions, relationship definitions, roles, tables, fields, markers, link-role variants, external languages, and output templates.
- Update text metadata such as name, summary, description, and TechSpec.
- Update safe definition metadata such as simple relationship flags, hidden-central settings, and text-safe template bodies.
- Retain legacy definitions and fields that exist only in the composition's embedded domain.

The merge does not:

- Delete definitions, tables, fields, roles, or templates by omission.
- Replace the embedded Domain object wholesale.
- Break existing ideas or relationship links in the composition.
- Execute TechSpec, templates, scripts, or external language text.
- Perform live synchronization after the command completes.

Dangerous changes such as field deletion, incompatible field data type changes, table deletion, or incompatible origin/target role changes are skipped by default and reported in the preview and application log.

Update dialogs separate `Source warnings` from `Import warnings`. Source warnings are preserved export notes from the selected `.tdom`/Domain JSON source, such as grouped missing-category notices or text-only template notes. Import warnings are generated by the current merge. A nonzero source-warning count can still be a clean update when `Applied skipped`, `Dangerous skipped`, `Import warnings`, and `Errors` are all zero.

## Command Boundary and Persistence

Updates run inside the active `CompositionEngine` command variation named `Update Embedded Domain`, so undo/redo can revert the merge when supported by the normal document edit engine. The composition is marked modified after a successful update. Save the `.tcom` normally to persist the new embedded domain snapshot.

After apply, ThinkComposer refreshes domain dependants and palettes when the existing services allow it.

## Manual Regression

1. Create a `.tcom` from an older `.tdom`.
2. Update the `.tdom` with new definitions, templates, tables, fields, or TechSpec.
3. Open the existing `.tcom`.
4. Run `Composition > Domain > Update Embedded Domain...`.
5. Select the newer `.tdom` or `samples/domain-sync-update.sample.json`.
6. Review the preview and apply.
7. Confirm new definitions appear in palettes/domain views while existing ideas remain intact.
8. Save, close, and reopen the `.tcom`.
9. Confirm the embedded domain changes persist.

## Troubleshooting

If an expected object is not added, check the lower-left application log for unresolved owner references, missing data types, missing external languages, or skipped dangerous changes. Name-only matches are intentionally not applied silently; add a stable `techName` or id to the source document.

If a change would remove or alter a field or role used by existing compositions, the first-pass updater preserves the existing embedded-domain object and logs a warning. Destructive cleanup and domain migrations are backlog work, not part of this safe merge command.
