# AI-Readable Container Snapshots

ThinkComposer `.tcom` and `.tdom` files are package containers. Modern saves use root JSON persistence parts as the native source of truth:

- `/Composition.json` for compositions.
- `/Domain.json` for domains and embedded composition domains.
- `/TemplateComposition.json` for optional domain template compositions.

Transitional packages may also contain `/Composition.bin` or `/Domain.bin`. Those binary parts are legacy fallback/recovery payloads, not the preferred load source when root JSON is present.

Current builds also write non-authoritative sidecar parts so tools and AI assistants can inspect saved files without first running a separate JSON export.

## Package Parts

Composition saves write:

- `/manifest.json`
- `/Composition.json`
- `/Domain.json`
- optional `/Composition.bin` legacy fallback
- `/Interchange/manifest.json`
- `/Interchange/Composition.json`
- `/Interchange/Domain.json`
- `/Previews/views/*.png`

Domain saves write:

- `/manifest.json`
- `/Domain.json`
- optional `/Domain.bin` legacy fallback
- `/Interchange/manifest.json`
- `/Interchange/Domain.json`

When a `.tdom` save includes a template composition, it can also write:

- `/TemplateComposition.json`
- `/Interchange/TemplateComposition.json`
- `/Previews/views/*.png`

The root manifest uses `format: "ThinkComposer.Package"` and `formatVersion: 1`; its schema is maintained at `docs/thinkcomposer-package-manifest.schema.json`. The sidecar manifest uses `format: "ThinkComposer.ContainerSnapshot"` and `formatVersion: 1`; its schema is maintained at `docs/thinkcomposer-container-manifest.schema.json`.

## Behavior

The root JSON payload is generated by the same Composition JSON and Domain JSON exporters used by the manual export commands, then loaded through a persistence rehydration path instead of a merge/import dialog. Opening a modern native file reads root JSON first. Opening a legacy binary-only file still reads `/Composition.bin` or `/Domain.bin`; saving it migrates the package to root JSON persistence.

Preview images are PNG v1. They are capped to keep saves safe and predictable. If a view has no renderable content, or a preview cannot be generated, the save still succeeds and the manifest/log records a warning.

Sidecar generation is non-blocking. A failure to write JSON or previews should not prevent a normal `.tcom` or `.tdom` save.

## AI Workflow

An AI tool can inspect a saved package by opening it as a zip/OPC package and reading:

1. `/manifest.json`
2. root `/Composition.json`, `/Domain.json`, or `/TemplateComposition.json`
3. `/Interchange/manifest.json`
4. the listed sidecar JSON parts
5. the listed preview PNGs

If embedded sidecars are missing or stale, inspect and patch the authoritative root JSON first. For explicit compatibility exports or visual verification, use:

- `thinkcomposer composition export-json --input <file.tcom> --output <file.json>`
- `thinkcomposer domain export-json --input <file.tdom> --output <file.json>`
- `Export Image`

## Migration Notes

Legacy binary-only `.tcom` and `.tdom` files remain readable. Newly saved files use JSON-authoritative persistence and may retain binary fallback parts only for recovery and compatibility during the transition.

Root JSON currently covers the documented Composition JSON and Domain JSON fields. Metadata-only warnings in the root JSON or package manifest identify native data that is intentionally not reconstructed from JSON, such as binary attachment payloads or custom binary image resources.
